# TradingAgents-CN 架构实践：用多智能体跑一份 A 股研报

> 本文为个人工程实践笔记，代码和架构为技术学习参考，不构成任何投资建议。金融市场有风险，且任何 LLM 输出都可能存在幻觉。

## 一、为什么单 Agent 做不好股票分析

市面上 90% 的"AI 炒股"工具，本质就是把用户输入塞给 ChatGPT / DeepSeek，让它直接输出一份研报。这种单 Agent 方案有三个硬伤：

1. **视角单一**：既当基本面、又当技术面、又当消息面，最后哪个都不精
2. **自我确认偏差**：模型会把自己的第一印象当成结论，不会反驳自己
3. **缺乏风控**：合规审查和分析混在一个 Prompt 里，风险提示常被淹没

于是 Tauric Research 在 2024 年提出 TradingAgents，用**角色分工 + 结构化辩论**解决上述问题。我基于这套思路做了中文版落地（在线试用入口：`nbstockai.com`），这篇博客分享架构细节与踩坑。

## 二、整体分层：4 层 / 7 个 Agent

```
┌──────────────────────────────────────────────────┐
│ 信息层  基本面 / 技术面 / 新闻面 / 情绪面（4 Agent）│
├──────────────────────────────────────────────────┤
│ 辩论层  看多分析师 ↔ 看空分析师（2 Agent）         │
├──────────────────────────────────────────────────┤
│ 决策层  交易员（1 Agent）综合多方输出              │
├──────────────────────────────────────────────────┤
│ 风控层  独立 LLM 做合规与风险复核                  │
└──────────────────────────────────────────────────┘
```

总计 7 个 Agent，配合 LangGraph 做状态流转。每层职责单一，可单独替换 / 测试。

## 三、信息层：4 个并行分析师

这一层是"数据加工厂"，4 个 Agent 互相独立，可并行执行：

- **基本面分析师**：读财报、算估值，数据源 Tushare / AkShare
- **技术分析师**：MA / MACD / KDJ，数据源 BaoStock
- **新闻分析师**：最近 30 天公告 + 新闻，数据源财联社 / 东方财富
- **情绪分析师**：雪球 / 股吧热度、讨论极性，数据源自建爬虫

### 工程细节 1：工具通过 LangChain Tool 注入

```python
fundamental_tools = [
    Tool(name="get_financial_report", func=fetch_tushare_report),
    Tool(name="calc_valuation", func=calc_pe_pb_dcf),
]
agent = create_react_agent(llm, fundamental_tools, fundamental_prompt)
```

模型不直接"知道"财务数据，而是通过 Tool 调用拿到 → 减少幻觉。

### 工程细节 2：4 个 Agent 并行 + 超时降级

```python
import asyncio

results = await asyncio.gather(
    run_agent("fundamental", stock_code),
    run_agent("technical", stock_code),
    run_agent("news", stock_code),
    run_agent("sentiment", stock_code),
    return_exceptions=True,
)
```

任一 Agent 超时（比如新闻爬虫抖一下），其它三个照常输出，总流程不挂。

## 四、辩论层：看多 vs 看空

信息层输出汇总后，送给两个对立 Agent 写辩论稿。关键是 **Prompt 强制站队**：

**看多 Prompt 片段：**
```
你是坚定的看多方。你必须基于四位分析师的输出，
找出所有支持看多的证据、反驳看空的逻辑。
即使基本面偏空，你也要从行业 β、估值修复、预期差等角度找多头理由。
禁止中立发言。
```

看空 Prompt 对称处理。

辩论 2~3 轮后交给交易员裁决。**这里有个坑**：如果两个 Agent 用同一个模型同一温度，辩论容易同质化。解法是：
- 看多用 DeepSeek（推理风格偏乐观），看空用 Claude（推理风格偏严谨）
- 或相同模型 + 不同 temperature（看多 0.5 / 看空 0.3）

## 五、决策层：交易员

交易员读三份东西：
1. 4 份分析报告
2. 多空辩论稿
3. 合规边界（禁止具体买卖点位）

输出固定字段：
```json
{
  "stance": "看多 | 中性 | 看空",
  "confidence": 0.65,
  "core_reason": "...",
  "bull_points": ["...", "..."],
  "bear_points": ["...", "..."],
  "watch_signals": ["财报 Q2", "批价跌破 2200"]
}
```

不输出 target_price / buy_price，保证合规。

## 六、风控层：LLM check LLM

很多同行跳过这一层，但合规风险很大。我用一个独立 LLM（冷启动、不看辩论过程）专门复核交易员输出：

- 是否出现"预测股价""推荐买入"等合规红线？
- 是否有免责声明？
- 是否存在自相矛盾的逻辑？

只要命中一条 → 自动打回 + 要求重写。这一层可以用更便宜的模型（如 Qwen-Turbo）降本。

## 七、耗时与成本实测

跑一份茅台完整研报，实测：

| 阶段 | 耗时 | Token 消耗（输入 + 输出） |
| --- | --- | --- |
| 信息层 4 并行 | 35~50s | 12K |
| 辩论 2 轮 | 40~60s | 16K |
| 交易员决策 | 10~15s | 3K |
| 风控审查 | 5~10s | 1.5K |
| **合计** | **90~135s** | **约 32K** |

以 DeepSeek 价格计算，一份研报成本 ¥0.2~0.3，完全能接受。

**对比单 Agent 方案**：单 Agent 15 秒出结果，但内容质量差 2~3 倍。详细的 A/B 对比数据我写在了个人复盘里，不在本文赘述。

## 八、踩坑清单

1. **API 限流**：4 Agent 并行直接打满 DeepSeek 默认 QPS，解法是加 semaphore
2. **上下文爆炸**：第三轮辩论容易超 128K，解法是辩论前把分析摘要压缩到 2K
3. **辩论同质化**：看多看空输出越来越像，解法是换模型或把辩论稿互喂时做关键词反转
4. **流式输出**：整个 pipeline 跑 2 分钟，前端必须流式输出中间产物，否则用户会走
5. **新闻时效**：新闻数据必须带 timestamp，老新闻会污染结论

## 九、什么时候不要用多智能体

不是所有场景都适合。单 Agent 够用的场景：
- 小白问题（"A 股怎么开户"）
- 概念解释（"什么是市盈率"）
- 新闻摘要

多 Agent 的收益真正体现在**需要多视角碰撞 + 合规审查**的场景，比如：
- 单股深度研报（我的主要用途）
- 组合配置建议（延伸方向）
- 重大事件影响分析（如美联储加息对行业的传导）

如果你也在做类似项目，推荐先从单股研报 Prompt 设计入手（比如茅台这种高质量覆盖的样本），再扩展到多 Agent；别一上来就 7 个 Agent，会被 Prompt 调试累死。
